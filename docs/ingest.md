# Ingest API: field and severity mapping

`POST /v1/ingest` maps every input format into the native item schema (`NativeItem` in [packages/ingest/src/schema.ts](../packages/ingest/src/schema.ts), published as JSON Schema 2020-12 inside [openapi/ingest.json](openapi/ingest.json)) and validates the result strictly: unknown properties, wrong types and out-of-range values are errors. Curl examples are in the [README](../README.md#ingest-api).

## Format detection

| Content-Type                                                                         | Format                                      |
| ------------------------------------------------------------------------------------ | ------------------------------------------- |
| `application/json`, `application/vnd.threatsieve.ingest+json`                        | native, or the envelope's `format`          |
| `application/stix+json` (any `version` parameter), `application/vnd.oasis.stix+json` | STIX 2.1 bundle                             |
| `application/csaf+json`, `application/vnd.oasis.csaf+json`                           | CSAF 2.0 document, or an array of documents |
| `application/osv+json`, `application/vnd.osv+json`                                   | OSV record, or an array of records          |

With `application/json` the body is one native item, an array of native items, or an envelope `{"format": "native|stix|csaf|osv", "default_tlp": "...", "items": [...]}` whose `items` are documents of that format. Anything else returns 415. Bodies are never sniffed for a format.

A single document is stored synchronously and returns `201` (created) or `200` (matched an existing item). Arrays, envelopes and STIX bundles are batches: they return `202` with an `ingest_id` (`inb_…`), per-item IDs and per-item errors, and are stored by the `intel-ingest` queue. If no item is valid the response is `400` with `error.items`. Each error has `index` (position among the produced items), `document` (position in the request), `source_ref` (STIX id, CSAF tracking ID or OSV id when known) and `issues` (`path` + `message`).

## Native fields

| Field                        | Rules and normalisation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`                       | `alert` or `advisory`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `external_id`                | Producer ID, at most 256 characters, no control characters. If absent, a `sha256:` digest of type, title, `published_at` and `cve_ids` is used and `external_id_source` is `derived`.                                                                                                                                                                                                                                                                                                                                                         |
| `title`, `summary`           | Markup tags, HTML comments, control characters, zero-width and bidi-override characters are removed; whitespace is collapsed (the summary keeps paragraph breaks).                                                                                                                                                                                                                                                                                                                                                                            |
| `severity`                   | `info`, `low`, `medium`, `high`, `critical`. See [severity mapping](#severity-mapping).                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `vendor_severity`            | The producer's own value (string or 0–10 number), stored unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `source`                     | `name` (required), `url` (http/https only), `vendor`. `name` is part of the deduplication key, compared case- and whitespace-insensitively.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `published_at`, `updated_at` | ISO 8601 with offset; stored as UTC with millisecond precision.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `cve_ids`                    | `CVE-YYYY-NNNN…`, uppercased and de-duplicated.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `cvss`                       | `version` (`2.0`, `3.0`, `3.1`, `4.0`), `score` 0–10 and/or `vector`. The vector must match the version. A missing score is computed from a v2 or v3.x vector; v4.0 vectors are validated but not scored.                                                                                                                                                                                                                                                                                                                                     |
| `affected_products`          | `product` (required), `vendor`, `versions` (`version`, `introduced`, `fixed`, `last_affected`, `limit`, `range`), `cpe` (2.2 or 2.3), `purl`.                                                                                                                                                                                                                                                                                                                                                                                                 |
| `indicators`                 | `type` (`ipv4`, `ipv6`, `cidr`, `domain`, `url`, `email`, `md5`, `sha1`, `sha256`), `value`, `confidence` 0–100. Defanged input (`hxxp`, `[.]`, `[@]`) is refanged, then validated: dotted-quad IPv4 only, canonical IPv6, credential-free http(s) URLs with the fragment removed, lower-case IDN-encoded domains, hex hashes of the right length. Each stored indicator has a defanged `display_value` (`hxxps[://]evil[.]example/a`, `192[.]0[.]2[.]1`, `2001[:]db8[:][:]1`, `x[@]evil[.]example`). Non-public IP ranges produce a warning. |
| `attack_techniques`          | `T1234` or `T1234.001`, uppercased.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `references`                 | `{url, title}`; http(s) URLs only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `tags`                       | Sanitised, de-duplicated case-insensitively.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `tlp`                        | `clear`, `white` (stored as `clear`), `green`, `amber`, `amber+strict`, `red`. Unmarked items get the envelope's `default_tlp`, otherwise `amber`; `tlp_source` records which.                                                                                                                                                                                                                                                                                                                                                                |
| `raw`                        | Any JSON value, stored without interpretation. Originals over 256 KiB are kept in R2. Whitespace and key formatting of the request are not preserved.                                                                                                                                                                                                                                                                                                                                                                                         |

Every change is listed in the stored item's `normalisation.changes` (`path`, `from`, `to`), and mapper notes such as dropped references or skipped pattern comparisons are in `normalisation.warnings`.

## STIX 2.1

Indicators, sightings and incidents become alerts; vulnerabilities and reports become advisories. Other objects (identities, marking definitions, relationships, attack patterns, malware and so on) are context only.

| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `external_id`                 | object `id`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `title`                       | `name`; sightings use "Sighting of" + the sighted object's name; otherwise type + id                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `summary`                     | `description`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `source.name`                 | `name` of the `created_by_ref` identity in the bundle, else `STIX`                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `published_at` / `updated_at` | `created` / `modified`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `vendor_severity`             | a custom `x_…severity` property, if present                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `indicators`                  | literal `=` comparisons on `ipv4-addr:value`, `ipv6-addr:value`, `domain-name:value`, `url:value`, `email-addr:value` and `file:hashes` (MD5, SHA-1, SHA-256) in `stix` patterns. Patterns are matched as text and never evaluated; other comparisons and pattern languages are skipped with a warning. Reports and sightings take the indicators they reference, dropping invalid values with a warning; an indicator object with an invalid value is itself rejected. `confidence` comes from the indicator. |

| `tags`                        | `labels`, `indicator_types`, `report_types`                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## Severity mapping

`severity` is chosen in this order and `severity_source` records which rule applied:

1. `provided`: the native `severity` field.
2. `vendor`: `vendor_severity` mapped with the table below. The original value is kept in `vendor_severity`; an unrecognised value adds a warning and falls through.
3. `cvss`: the CVSS score's qualitative band.
4. `default`: `info`, with a warning. Treat `severity_source: default` as "unknown".

| Severity   | Vendor values (case-insensitive; `_` and `-` read as spaces)                      |
| ---------- | --------------------------------------------------------------------------------- |
| `critical` | critical, crit, urgent, emergency, very high, P1, Sev1 / severity 1 / priority 1  |
| `high`     | high, important, severe, major, P2, Sev2                                          |
| `medium`   | medium, moderate, med, warning, warn, elevated, P3, Sev3                          |
| `low`      | low, minor, P4, Sev4                                                              |
| `info`     | info, informational, information, none, negligible, notice, unimportant, P5, Sev5 |

Numbers and numeric strings from 0 to 10 are read as scores and use the CVSS bands: 0 → `info`, 0.1–3.9 → `low`, 4.0–6.9 → `medium`, 7.0–8.9 → `high`, 9.0–10.0 → `critical` (FIRST CVSS v3/v4 ratings). CVSS v2 has no Critical band, so v2 scores of 7.0 and above map to `high`.

## Deduplication and idempotency

The stored item ID is derived from the tenant, the normalised source name and the external ID, so the same item from the same source always lands on one row. A repeat updates the row and increments `revision` when its content differs and its `updated_at` (else `published_at`) is not older than the stored one; identical or older copies leave it unchanged. Within one request a later copy supersedes an earlier one. `Idempotency-Key` (1–200 characters) is separate: a retried request with the same key and body returns the first response with `Idempotent-Replayed: true`; a different body returns 409 `IDEMPOTENCY_CONFLICT`.

## Security

- Every payload is untrusted. Bodies over 5 MiB return 413 before or while streaming; more than 500 produced items return 413 `TOO_MANY_ITEMS`.
- Nothing in a payload is fetched, executed or evaluated. URLs are validated and stored as text; STIX patterns are read with a fixed regular expression.
- Display text is sanitised as above, indicators carry a defanged `display_value`, and responses are JSON with `nosniff`. Renderers must still escape text.
- Authentication reuses ThreatSieve API keys (`ingest:write`, `ingest:read`; session roles: admin and analyst get both, viewer gets read). `ingestSources` on a key limits the source names it may submit. Ingest has its own rate-limit bucket: `INGEST_RATE_LIMIT` requests per minute per key (default 60) and five times that per tenant.
- Each request is audited with the user, key, source IP, format, counts, sources and item IDs (`ingest.item`, `ingest.batch`, `ingest.rejected`). Titles and indicators are not written to the audit log or to Worker logs.
- Items are tenant-private. `GET /v1/ingest/{id}` only answers for the submitting tenant, so TLP:RED, AMBER and AMBER+STRICT items are never visible to another tenant. Ingested items are not yet added to the shared intelligence graph or any export; a future feed into those must keep RED and AMBER items tenant-scoped.

## Metrics

Each request logs one JSON line with `stage: "ingest"`, `format` and `items_received`, `items_accepted`, `items_rejected`, `items_deduplicated` (plus `items_created`/`items_updated` once stored). Daily per-tenant counters are kept in `ingest_metrics` and returned by `GET /v1/ingest/metrics?days=7` (`ingest:read`). `accepted` counts valid items including copies superseded within the same request; `deduplicated` counts those copies plus items that matched a stored item.
